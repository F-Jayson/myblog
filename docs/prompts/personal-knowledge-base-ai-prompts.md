## B. 开始实施 V1 的总提示词

**仅当你批准设计并决定开始编码时，复制下面整段。** 若只想开发一部分，将“实施完整 V1”替换为明确的阶段，例如“只实施 P1”，并追加对应的 C 控制卡。

```text
我已批准本项目的个人知识库设计，现在授权你在本地实施完整 V1（P1–P5）。P6 远程 HTTP MCP 后续单独实施。本次不授权 commit、push、部署、重启生产服务或操作生产数据库。

你是负责落地的全栈工程师，请持续推进到授权范围真实完成，不要只给建议、演示页面、mock API 或未验证的代码。

【必须先读】
工作区 F:\@ts\myblog。
1. AGENTS.md。
2. docs/superpowers/specs/2026-11-05-personal-knowledge-base-design.md，作为本次设计依据。
3. 如已有经确认的实施计划，读取它并核实其与现有源码是否一致。
4. package.json、pnpm-workspace.yaml、database/schema.sql、apps/api/src/cli.ts。
5. apps/api/src/server.ts、repository.ts、agentRoutes.ts、agentStore.ts、storage.ts、telemetry.ts 中与本任务相关的实际路径。
6. packages/blog-mcp/src/index.ts、credentials.ts、blogClient.ts，以及 docs/agent-tools.md。
7. apps/web/src/auth.tsx、UserTools.tsx、App.tsx、MarkdownContent.tsx、admin/MdEditorBridge.tsx 和实际主题样式。

先执行只读的 git status 和相关代码检查。工作区可能有用户未提交修改及未跟踪 JS 文件，不能清理、覆盖或夹带修改。Firefly-master 是独立参考项目；若目录不存在，说明现状并参考现有页面与 https://firefly.cuteleaf.cn/，不要声称已阅读不存在的目录。

【产品与技术边界】
- 沿用 React + Vite、Express + TypeScript、MySQL 和 pnpm；知识库是现有博客模块，不迁移技术栈，不拆微服务。
- 普通用户主体是 comment_users。admin_users 与其隔离，数字 ID 相同不代表同一身份。
- 内容以 Markdown 为唯一权威格式；首版非实时协作，所有 Web/MCP 更新有版本冲突保护。
- 实现知识库、目录/文档、标签/来源、引用/反向引用、搜索、历史/恢复、回收站、附件、导入导出、评论与共享。
- 普通用户公开知识不获得站长 posts 管理权，不自动把用户笔记发布成博客文章。
- 不增加实时协同、Notion 数据库视图、公式、向量数据库、RAG 聊天、微服务或无依据的队列/缓存设施。

【资格与活跃】
- 严格使用注册年龄 > 30×24小时，而不是 >=30 或前端自报天数。
- 按设计统计 30 个已完成 UTC 日的真实业务事件；最近登录时间不足以证明历史活跃。
- 使用设计中的 D/U/S/W 公式、日上限、去重和规则版本；MCP、自动轮询、失败请求、自动保存不计分。
- 所有鉴权成功别名与业务成功路径一致计数，事件必须幂等，不能在事务失败时计分。
- 实现明确的 locked/eligible/active/grace/read_only/suspended 状态。读写能力、库所有者与协作者资格按设计统一判断。
- 降活跃不删知识；允许按设计读取、导出、撤销授权和收紧共享。不给管理员或新账号添加未设计的门槛绕过。

【权限是服务端规则】
- 所有查询、搜索、目录、评论、历史、附件、导出、分享链接和 MCP 共用权限服务。
- 实现 owner/manager/editor/commenter/viewer；具名共享与匿名发布是不同访问通道。
- 支持库成员、单篇/子树授权、restricted 祖先上限、members_only、撤销和移动造成的受众变化；严格遵守设计的计算顺序。
- AI 移动整个子树的继承访问范围发生变化时，同时要求 write + share 和对应角色/资格；不能以目录整理绕过共享授权。
- 写入先根据服务端会话或 grant 确认主体，再验证资源所属关系；不能信任客户端 ownerId/userId。
- 保存只更新工作版本，公开读取只取 published_revision_id 对应的完整快照，草稿标题/正文/附件/引用也不能泄露。
- 权限撤销和写入须有确定事务顺序；缓存、分享会话和 token 都不能保留已撤销的访问能力。
- 附件绑定、引用、复制、发布和下载分别验证来源访问权，不能通过“同库”判断搬运受限文件。

【可靠保存与数据生命周期】
- 使用 expectedVersion 和原子更新，冲突返回 409；缺少版本不能默默覆盖。无变化不新建 revision。
- Web 串行自动保存，冲突保留本地输入；AI 更新先读当前版本，重试有上限，不无条件覆盖。
- 写操作有幂等键，externalKey 同步不得绕过版本检查。
- 配额按库 owner 统一加锁计算；沿用设计的独立额度，不改坏原有 30 MiB 用户空间。
- 处理回收站、版本保留、附件引用/暂存/删除重试、导出撤权、用户禁用/删除及其所有调用入口。
- 有归属知识库（含回收站/待清理数据）的 owner 硬删除返回 USER_OWNS_KNOWLEDGE_DATA；纯协作者注销不删除他人库的修订与评论。恢复库/文档不自动恢复公开状态和旧分享链接。
- 新接口不得把正文、代码、密码、token、设备码、分享秘密和搜索词写入通用审计、代理日志或监控路径。

【普通用户 MCP】
- V1 提供独立的知识库本机 stdio 适配器和普通用户浏览器授权，复用业务逻辑，不复用管理员 grant/凭据。
- 新适配器选择实施时维护中的官方 SDK，锁定实际兼容的协议版本；不得照搬旧包的手写帧或任意回显协议版本。
- 默认只读，用户明确选择库、scope 和有效期。新增库不自动加入已有授权，敏感 scope 默认关闭。
- 每次调用校验账号、grant、选中资源、实时 ACL、资格、scope、配额与版本；没有 scope 就拒绝，不能依赖工具描述当权限。
- 密码仅在本站浏览器登录，MCP 不接收密码和浏览器 session；不打印 token，不把凭据放进聊天或仓库。
- 支持知识库连接管理、撤销、过期、改密撤销、账号隔离以及多账号本地 profile。
- 正常保存不要求反复重新授权；公开、共享、删除等使用独立工具及用户预先授予的敏感 scope。
- 完整实现设计工具清单，不能只加几个 tool 名称而没有业务路径。HTTP OAuth 属于 P6，不能宣称 V1 已兼容远程客户端。

【实施方式】
先将设计转成可执行计划并保存；这是执行准备，不需要每个阶段重复请求授权。发现新的实质性范围冲突时暂停受影响部分，继续独立可完成的工作并说明。
按 P1→P2→P3→P4→P5 实施，保持每阶段可验证。业务代码按真实职责拆分，不扩大现有 server.ts/repository.ts 成为所有逻辑的容器，也不创建无用抽象层。
有技术不确定性时核对实际源码、目标 SDK 和一手官方文档，不根据旧教程推断兼容。
新功能默认关闭；迁移在隔离的 MySQL 测试数据库验证空库、存量和重复执行，不运行生产 seed，不自动发布。

【验证与交付】
建立覆盖设计 A01–A22 的必要测试：纯规则单测、真实 MySQL 权限/事务/并发测试、HTTP 集成测试、前端关键流程、真实 MCP 客户端或 Inspector 互通。
至少使用 A/B 两个普通账号、一个受邀协作者和管理员对照身份，验证 ID 替换、scope 越权、草稿泄漏、撤销后读取、保存冲突和并发配额。
运行适合本仓库的 type-check、build 和新增测试，记录实际命令与结果。不要把预期写成通过；基线失败与新增失败分开说明。
更新功能、接入、配置、数据迁移与关闭功能说明，给出可复现验收步骤。不要宣称审计了全部系统或已经生产上线。
最终说明：完成范围、关键文件、实测结果、剩余限制、P6 尚未实施、如何本地验收。未经另行明确授权，不 commit/push/部署。
```

## D. 独立审阅与验收提示词

```text
你是独立审阅者。只审阅，不修改文件、不部署、不操作生产。
读取个人知识库设计、当前实施计划、实现 diff 和实际测试记录。不要直接采信实现者“已经通过”的口头结论。

按严重性检查：
1. 普通账号与管理员是否真正隔离，所有资源入口是否按同一主体和 ACL 校验。
2. 活跃资格与宽限是否自洽、是否能被客户端/MCP/并发和旧路由绕过。
3. restricted 祖先、单篇授权、目录移动、搜索计数、引用、评论、历史与附件是否泄漏。
4. 草稿与公开快照是否彻底分离；附件绑定/复制有没有来源访问检查。
5. 并发修改、撤销竞争、幂等重试、配额、回收站和账号删除是否会丢数据或越权。
6. MCP 是否真实互通、scope/资源范围/撤销是否由后端落实，凭据是否进入日志或工具返回。
7. 是否改动了无关用户工作、原博客行为，或引入未要求的实时协同/搜索基础设施。

对发现给出可复现触发条件、实际影响、文件与行号、最小修复建议。区分已证实问题、设计矛盾和未运行检查，不把猜测写成事实。
如果没有阻断项也列出尚未验证的必要验收；不能把“未找到问题”等同于全部通过。
```
